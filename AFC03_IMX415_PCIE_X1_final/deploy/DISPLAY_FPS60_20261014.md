# 1080p 显示路径 30 FPS 修正

现有上板日志中，源端约 60 FPS，raw 无显示输出约 60 FPS，而 KMS 显示稳定在 29.95 FPS。因此本次修改播放软件，不修改 FPGA 位流、驱动或 v26 回退工程。

`display_lz77_video.py` 在 kmssink 支持 `skip-vsync` 时启用该属性，避免内部额外垂直同步等待造成帧率减半。`sync=false` 本身不能关闭这层等待。官方说明：https://gstreamer.freedesktop.org/documentation/kms/index.html#kmssink:skip-vsync

V4L2 输入明确协商 1920×1080 RGB 60/1；LZ77 rawvideoparse 和 YOLO appsrc caps 统一为 60/1。没有插入 videorate，没有复制旧帧补足 FPS。界面 FPS 继续使用实际 sink 计数，不把 caps 中的 60 当作实测值。

运行日志会输出 `KMS skip-vsync=true` 和完整 `PIPELINE`。不支持该属性的插件保留兼容播放，并提示 `KMS skip-vsync unavailable`；此时需更新板端 kmssink，不能宣称半速问题已修复。官方标准属性从 GStreamer 1.22 提供，厂商版本是否支持以实际插件属性为准。

停止旧播放进程，将更新的完整 deploy 内容同步到 `/home/linaro/deploy/`，保留板端已有 .ko、编译后的接收程序和本地配置。此次不用重新综合或烧录 bit；继续使用用户从原工程生成的 compress 版本 bit。

```bash
cd /home/linaro/deploy
sha256sum -c SHA256SUMS
python3 -m py_compile display_lz77_video.py
gst-inspect-1.0 kmssink | grep -A 3 skip-vsync
bash validate_board_clock.sh raw
bash validate_board_clock.sh display
```

普通模式目标：源端、raw OUTPUT 和 DISPLAY 均接近 60 FPS（显示器当前模式也应为 60 Hz）；硬件错误计数不增加。若仍显示 30，检查 gst.log 是否包含上述 skip-vsync 标记，用 `modetest -M rockchip -p -c` 检查当前 CRTC 刷新率和 connector 188，再比较 hardware.log 和 headless 输出。FPS sink 计数并非对物理屏幕扫描或端到端延迟的直接测量。

灰度实时播放：

```bash
cd /home/linaro/deploy
YOLO_MODEL= bash play_raw_video.sh 1 188
```

LZ77、YOLO 单独或同时开启仍需分别实测。60/1 caps 只描述流格式，不证明这些路径达到 60 FPS 或 20–30 FPS。
