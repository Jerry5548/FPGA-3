日志：`dma-profile.DrzkAM`，v32，mode 8，1920×1080 RGB24，BLK1，4 KiB read，完整 ARM CRC。
收到300个完整帧，CRC/decode/format、FPGA错误及首错快照均为0，receiver_exit/test_exit均为0。
300帧均为tokens=0、payload=6222320 bytes，是原始块回退，压缩匹配优化不能改善这批数据。

- calls=456073，completed_bytes=1867005808，测量区间18.776505秒，约99.433 MB/s；
- 接收器完整300帧耗时18.776461秒，15.977 FPS，包含约1秒启动等待；
  该数又受驱动计时开销影响，不能直接与无计时的17.5 FPS比较；
- 平均每次调用36.445微秒，submit=34.954微秒；
- submit内：queue/start=4.342微秒，poll_kick=1.321微秒，completion_wait=27.341微秒；
  completion_wait占submit约78.22%，占整个测量调用约75.02%；
- user_map=0.928微秒、user_unmap=0.377微秒，描述符构建仅0.309微秒；
- 300次short read与每帧尾包532 bytes吻合，errors=0、zero_reads=0、poll_empty=0；
- 结束时DDR_NO_SLOT=763，DDR_STARTUP_SKIPS=1。源帧号跳跃是整帧跳过，不是字节丢失；
- 生产线程预读超过300帧边界的73次read解释了driver calls大于接收器reads，不能混为额外输出帧；
- dmesg.before与after字节相同，没有本轮新增内核日志；最大单调用约1035 ms包含启动等待，
  不应解释为每帧存在1秒卡顿。

这些数据支持尝试减少完成等待中的睡眠/唤醒开销，但不证明27.341微秒全是调度浪费。
仍可能包含FPGA供数、DMA和完成线程等待；本候选是可关闭的实验，不保证提升。

## 候选实现

新增模块参数 `st_c2h_wait_spin_us=0..50`，默认0，保持原等待行为。
仅poll线程存在、单描述符、4 KiB ST C2H同步请求参与；H2C、整帧V4L2、循环DMA、
IRQ模式和带自定义controls的请求跳过该候选。与完成线程同CPU也跳过，避免挡住完成线程。

提交并唤醒原poll线程后，调用read的任务在有限预算内观察transfer state，尝试让已快速完成的
传输避免进入睡眠。它不读取/清除writeback、不处理描述符或transfer链表、不修改EOP和数据长度。
原完成线程继续负责完成处理；超出预算、signal_pending或need_resched立即回到原等待宏。
现有timeout、错误处理和engine锁内的最终状态检查保留。不提高任务实时优先级、不改CPU绑核。
时间预算按墙钟检查，正常抢占可能让一次观察区间超出预算，并非严格实时上界。

代价是增加CPU忙等，可能影响YOLO；本次不把候选默认开启，也不自动选择20或50微秒。
若FPGA仍未提供数据，忙等不会创造吞吐；若同CPU或调度负载高，选项可能几乎不起作用。

profile.stats增加可选字段wait_spin_calls、wait_spin_ready和wait_spin_ns。
wait_spin_ns已经包含在completion_wait_ns中，不能再次相加。
ready只表示状态不再SUBMITTED，必须另检查errors，不能把FAILED当作成功。
未启用profile时没有这些聚合统计开销；设置0时不进入计时/忙等。

## 第二步：编译通过后才更换并对照

先停止网页或终端启动的所有播放/采集，再在同一root PuTTY确认无占用。
记录第一步输出的备份目录，留作回退。不要在设备仍被占用时执行卸载。

```bash
cd /home/linaro/deploy
(
  set -e
  if fuser /dev/ANLOGIC-PCI0_c2h_0 /dev/video73 2>/dev/null; then
    echo '设备仍在使用，请先停止播放'; exit 1
  fi
  busybox devmem 0x21200060 32 0
  rmmod milianke_v4l2
  rmmod anlogic_pci
  insmod ./sgdma_drv/anlogic_pci.ko poll_mode=1 enable_st_c2h_credit=1 \
    force_st_c2h_wb=0 desc_blen_max=1048576 interrupt_mode=1 \
    c2h_timeout=10 h2c_timeout=10 st_c2h_wait_spin_us=0
  insmod ./v4l2_drv/milianke_v4l2.ko
  cat /sys/module/anlogic_pci/parameters/st_c2h_wait_spin_us
)
```

最后应显示0；加载失败就停止并用备份模块恢复，不继续对照。以上参数来自此次config.log。
加载成功后，同一root PuTTY执行：

```bash

set -o pipefail
bash test_dma_wait_ab.sh 300 8 2>&1 | tee /home/linaro/dma-wait-ab-console.log
```

自动按0/10/20/0微秒运行四组300帧验证，每组保存CPU计数和DMA阶段数据。
首尾重复0用于观察场景/温度漂移；任何完整性测试失败即停止。
脚本结束关闭profile并恢复开始时预算，输出`/home/linaro/dma-wait-ab.*.tar.gz`，用Xftp下载。
若测试前是0，结束后也回到0。阶段计时本身有开销，不用计时开启时FPS作最终验收。

只有确认候选在无计时状态下确实提速且没有错误后，再测试stats/KMS及YOLO竞争，
