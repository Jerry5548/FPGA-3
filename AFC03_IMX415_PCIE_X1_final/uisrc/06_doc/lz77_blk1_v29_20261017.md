## 失败原因和修正

旧 formatter 用 byte-wide 数组同时多地址写入、组合多地址读取。TD 在 syn_1/run.log
报告两条 SYN-5114，每块 RAM 将使用 524288 个寄存器，随后内存峰值约 19.6 GB 并 coredump。
PRJ-8001 是该异常退出的汇总，并非已定位到 PCIe 或 UI PLL 的问题。

新结构为两块 `4096 × 128-bit` 同步 RAM，各 64 KiB，明确的单写端口和同步读端口；
使用项目现有的 `ram_style="bram(min_area)"`。RAM 数组和读寄存器不复位，
有效长度、状态与打包寄存器复位；旧内容不能通过新帧计数暴露。

输入每次固定存入 4 个真实原始字节，使用 128-bit pack/carry，每次最多一次整字写入。
token 流同样 pack/carry 至 128-bit，只暂存最多 64 KiB；累计 token 长度达到原始块上限后
置位回退状态，避免 token 计数回绕或写越界。压缩路径严格要求 stored_len < raw_len。
第一批数据之后继续收集整块，收到 encoder 块尾并排空待决 token 后才比较长度和输出块头。

每个块在 encoder 端独立开始/结束，后续块不引用前一块历史。块尾等待 formatter 的
block_done 后才接收下一块，frame_last 独立保留至当前块 footer。同步 RAM 读延迟和输出
背压已处理，输出停顿期间 data/keep/last 稳定。当前为收集/输出轮流使用的缓存，
并非两个块并发的 ping-pong；不能据此承诺板端 FPS。

CRC 使用生成的 GF(2) XOR 表达式处理 2..16 个偶数字节，保持 IEEE CRC32 多项式及
旧初末取反。CRC 覆盖块头和 stored bytes；footer raw/comp/tokens 按实际选择累计。
0xb0 在 v29 为实际 BLK1 payload 字节数（包含块头）；v28 旧诊断语义仍保持。
