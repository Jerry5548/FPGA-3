# FPGA—RK3576 PCIe 图像传输与边缘处理项目阶段技术报告

报告日期：2026 年 10 月 16 日  
报告性质：基于官方工程的二次开发成果与阶段验收情况  
目标平台：AFC03／PH1A90 FPGA、IMX415 摄像头、RK3576  
工作工程：D:\FPGA\AFC03_IMX415_PCIE_X1_test\IMX415_PCIE_X1  
统计截止：本次会话已提供的上板记录与本地构建／仿真记录；本报告未新增上板测试。

## 摘要

本项目在官方 IMX415→FPGA→PCIe→RK3576 图像采集及 YOLO 示例基础上，完成了可切换图像预处理、DDR 完整帧缓存、LZ77 编解码与 CRC 校验、解压图像显示、YOLO 同帧检测显示、性能监测及部署管理等扩展。针对源端帧率异常和显示半速问题，修正了摄像头时钟配置、PH1A MIPI 延时控制与扫描边界，并调整显示同步设置。

目前已取得普通灰度显示约 60 FPS、灰度＋Sobel 显示约 60 FPS 的用户上板反馈；原图＋YOLO 屏摄显示约 24 FPS，单次 NPU 调用约 28.5 ms。上述结果均保持 1920×1080 显示输入，不通过降低图像分辨率或补充重复帧实现帧率数字。YOLO 网络输入仍按官方模型缩放到 640×640。

LZ77 全链路已实现可运行与完整性检查，但原图实测约 2.65 FPS，且本轮负载膨胀至原始图像的 1.855 倍，尚未实现通用场景带宽节省与 20–30 FPS 目标。最新编码器局部吞吐、16 KiB 分包及 64 KiB 接收缓冲优化已形成候选代码，其中 RTL 功能仿真通过，综合后时序与板端收益尚待验证。LZ77＋YOLO 还存在 native 内存异常退出，不能宣布组合模式完成验收。

## 1. 官方基础与开发边界

### 1.1 官方基础能力

本地官方资料包含 PH1A90SEG324 工程、IMX415/MIPI/ISP 图像链路、PCIe/SGDMA、RK3576 V4L2 驱动、初始化与诊断脚本，以及独立 YOLO 示例。官方部署说明以 1080p60 为目标格式，使用 V4L2/GStreamer 输出 RGB 视频。官方已有“高速采集＋PCIe 传输＋YOLO 应用”的基础框架。

本项目继续使用官方／厂商 PCIe IP、SGDMA 和原图采集路径，并沿用官方 yolov5s_relu.rknn 模型。新增成果主要属于图像算法移植集成、数据完整性设计、压缩传输链路开发、时钟与时序修正、性能定位及工程化部署。中值/Sobel 来自用户指定的另一 MIPI 工程，不表述为本项目首次提出这些算法。

## 2. 已形成的系统架构

普通路径：IMX415 → MIPI/RAW10/ISP → 预处理选择 → RGB24 打包 → PCIe C2H → V4L2 → 可选 YOLO → OSD/KMS 显示。

压缩路径：IMX415 → MIPI/ISP → 预处理选择 → DDR 完整帧双槽 → LZ77 子集编码 → 帧头／负载 CRC32／帧尾 → PCIe C2H → C 接收器校验与解码 → RGB24 管道 → 可选 YOLO → OSD/KMS 显示。

控制路径：RK3576 通过 PCIe BAR0 寄存器进行预处理选择、压缩开关、启停与软复位，并读取相机、压缩、DDR 和首错快照。

PCIe 链路仍为 Gen2 x1，上板读回 5 GT/s、x1。本项目没有将链路升级为更高代际或更宽通道，也没有自行替代厂商 PCIe 硬核。

## 3. 主要技术成果

### 3.1 多模式图像处理与模式控制

| 模式 | 功能 | 说明 |
| --- | --- | --- |
| 0 | 原图 RGB | 原始彩色路径 |
| 1 | 灰度 | 灰度值复制到 RGB24 三通道 |
| 2 | 灰度＋高斯滤波 | 平滑降噪 |
| 3 | 灰度＋直方图均衡 | 提升对比度；动态切换仍有回归问题 |
| 4 | 灰度＋高斯＋直方图均衡 | 组合预处理 |
| 5 | 灰度＋3×3 中值 | 从用户指定 MIPI 工程移植的降噪模块 |
| 6 | 灰度＋3×3 Sobel | 默认阈值 128 的二值边缘图；不是 Canny |
| 7 | 预留 | 未实现，脚本拒绝选择 |

预处理以四像素并行接口接入原图像链路，保留 SOF/EOL 和图像尺寸；现有处理针对 1080p 配置，其他分辨率不纳入本阶段验收。Sobel 阈值为编译参数，尚无运行时阈值寄存器。中值和 Sobel 为并列可选模式，模式 6 不自动串联中值滤波。

### 3.2 DDR 完整帧缓存及异常隔离

新增压缩支路 DDR 双槽设计，将摄像头不可反压的实时输入与慢速编码消费者分离。只有完成帧长度、行尾／帧尾和总线响应检查的帧才发布给后级；槽位忙时按整帧跳过，并记录 DDR_NO_SLOT。

增加启动帧跳过、捕获 ID、DDR 无效帧计数、AXI 读写错误和采集 FIFO 丢数计数。BAR0+0x100～0x11C 提供 256 位首个 DDR 拒收帧现场，使用握手邮箱跨时钟域传递，包含原因、帧号、位置、已收字数和标记。

上述机制提高了异常可定位性与帧边界保护能力，但不等于连续 60 个摄像头曝光全部被压缩。DDR_NO_SLOT 非零意味着仍有整帧被跳过；CRC 通过不能证明跳过帧不存在。

### 3.3 LZ77 传输协议及 RK3576 接收解码

建立 16 字节帧头、Token 负载和 20 字节帧尾的协议，包含图像尺寸、帧号、原始字节数、压缩字节数、Token 数和负载 CRC32。

当前编码器是 distance=1 连续重复匹配的 LZ77 子集，没有实现通用滑动字典搜索；literal 采用两字节格式，复杂原图可能出现负压缩收益。对其准确表述应为“LZ77 子集压缩链路”，不能表述为成熟通用高压缩率编码器。

C 接收器支持任意短读分片拼接、帧同步、CRC 校验、RGB24 长度检查、Token 解码、帧文件输出和实时 RGB24 输出。新增缺失帧尾边界约束，避免异常流无限累积；输入文件与字符设备按类型处理，避免离线测试文件被误截断。Python 参考解码器、几何与多帧输出测试用于交叉校验。

### 3.4 摄像头时钟及 MIPI 接收修正

定位到源端实际 12 MHz MCLK 与 27 MHz 传感器配置不匹配的问题，其频率比例与旧测约 26.669 FPS 一致。重新生成 UI PLL 配置，C0/C1/C2 为 150/90/54 MHz，C2 二分频形成设计值 27 MHz MCLK，I²C 分频设为 539，默认使用摄像头模式 0；核对 RAW10、binning 和行场参数。

修正 PH1A 延时使能与加载脉冲混淆、5 位物理档位被按 64 档扫描、全窗口长度溢出等问题。采用厂商 IDELAY 模型验证延时持续有效与扫描边界，并通过旧源码复现错误。

修复后 source 测试的五个区间读数为 60.329、59.889、59.859、60.376、59.871 FPS，区间读数算术平均约 60.065 FPS。此计数来自 FPGA 打包帧事件，不是对传感器 XVS 或 MCLK 的直接物理测量；MCLK 引脚独立仪器测量尚未纳入证据。

### 3.5 显示半速问题修正与实时统计

对比源端约 60 FPS、无显示采集约 60 FPS、KMS 显示约 29.95 FPS，定位显示路径同步问题。显示模块在支持时启用 kmssink skip-vsync，V4L2 与解压输出协商 1080p60，并保留单帧有界队列。

屏幕左上角集中显示实际 DISPLAY FPS、LZ77 解码输出 FPS、YOLO FPS、单次 NPU 耗时、模式和检测数量。FPS 来源于实际完成计数，而非固定显示 caps 中的 60。用户随后反馈灰度与灰度＋Sobel 均约 60 FPS，支持显示半速问题已解除；尚未取得长期多轮统计及逐帧唯一性验收。

### 3.6 YOLO 集成与性能分解

沿用官方 yolov5s_relu.rknn，使用 RKNNLite 和 RK3576 NPU，网络输入 640×640。统一模型路径处理，适配 /home/linaro/rock/yolo，避免另启一个官方采集进程争抢设备。

实现从本项目输入流取图、letterbox、颜色顺序适配、后处理、检测框映射与同帧绘框显示；增加等待、预处理、NPU、后处理、绘框及显示提交分段计时。对后处理先做阈值筛选以减少无效候选计算，并保留离线等价测试。

用户屏摄中原图＋YOLO 显示 FPS=23.7、YOLO FPS=23.9、NPU=28.5 ms、DET=0。这证明本项目 YOLO 应用路径可运行，单独开启时处于 20–30 FPS 区间；不能用该单个画面宣称长时间平均性能、密集检测性能或准确率提升。项目尚未开发或验收新训练模型。

## 5. 最新吞吐优化的实际进度

| 优化项 | 当前实现 | 验证状态 | 尚缺工作 |
| --- | --- | --- | --- |
| 编码器 literal 流水重叠 | 发射 seed 同时接收下一字节 | 独立 A/B：10,000 字节，20,000→10,002 拍；长短重复／停顿及字节校验通过 | 仍为单字节输入，非多字节并行；需重新实现和上板 |
| 更大 C2H 逻辑包 | 顶层 EOP 间隔 1 KiB→16 KiB | packetizer 满包和最终短包仿真通过 | 实际 SGDMA 完成、尾包与启停测试 |
| RK 接收请求缓冲 | 4 KiB→64 KiB，对齐与短读解析保留 | 源码已同步；Windows 当前无 Linux C 构建环境 | 板端编译、自测、吞吐对照 |
| 灰度单通道 | 未实现，仍为 RGB24 | 无 | 定义像素格式、编码解码及显示适配 |
| DMA 连续缓冲／描述符预提交 | 未实现 | 现有驱动仍同步提交、等待、map/unmap | 所有权、取消、复位与持久缓冲设计 |
| 接收—CRC—解压流水 | 未实现 | 当前逐帧串行，仍有分配／拷贝／管道写入 | 有界缓冲、CRC 加速、缓冲复用及并发验证 |

理论约束：单字节输入在 125 MHz 下至多约 125 MB/s。1080p RGB24 每帧 6,220,800 字节，20／30／60 FPS 分别要求 124.416／186.624／373.248 MB/s 原始吞吐。当前单字节链路几乎没有实现 20 FPS 的停顿余量，30 FPS 需更高并行度。局部接近两倍吞吐不能等同总链路两倍 FPS。

在原图 C/R=1.855221 的本轮条件下，20／30 FPS 约需 230.8／346.2 MB/s 压缩负载，还未计协议开销；即使并行编码完成，也需评估压缩膨胀、主机吞吐及链路效率。

## 7. 问题清单与后续验收

| 问题／缺口 | 当前判断 | 后续验收 |
| --- | --- | --- |
| LZ77 原图约 2.65 FPS | 压缩路径吞吐不足，不能归因于整个 PCIe 只能达到该速率 | 同场景候选／基线对照，记录 comp_frames、read_wait、CRC、解码、显示和跳帧 |
| LZ77＋YOLO 异常退出 | gst.log 有 corrupted size vs. prev_size；具体 native 损坏来源未定位 | 获取 native 回溯，验证启停、内存所有权和异常处理 |

| PCIe 时钟告警 | IP 重生成后 USR-6144 仍在；工具推导频率不等于硬件测频 | 动态时钟约束核验与实现审查 |
| 最新 RTL 时序／资源 | 未取得覆盖新候选的实现结果 | 重新综合／布局布线，检查时序、资源和 CDC |

| 长时间稳定性与图像完整性 | 普通显示用户反馈成功，不等于逐帧完整性验收 | 连续测试、唯一帧号、像素完整性；检查驱动短帧接受策略 |

建议后续保持 1080p，不以降分辨率或重复显示补帧替代有效吞吐，先独立提高压缩供帧速度，再验证 LZ77＋YOLO 同开。正式验收除 FPS 外，还需报告压缩率、错误计数、整帧跳过率、端到端延迟、资源、时序和检测准确率。

## 8. 阶段结论及可提交成果表述

本项目已在官方采集、PCIe/DMA 和 YOLO 基础上，形成“FPGA 可切换图像处理＋DDR 完整帧管理＋PCIe 压缩／非压缩双路径＋RK3576 校验解码与智能显示”的可运行平台。已解决本项目配置中的源端低帧率和显示半速问题，普通灰度及 Sobel 显示达到约 60 FPS；原图与官方 YOLO 集成达到约 24 FPS。完成了压缩传输协议、异常隔离和性能诊断工具，为后续带宽优化提供了可量化基础。

目前项目属于功能闭环和性能优化阶段，尚未完成多字节并行压缩、灰度单通道、DMA 描述符预提交及 RK 接收流水化，LZ77＋YOLO 的 20–30 FPS 总体目标未达成。上述边界应与已取得的成果一起提交，不将候选仿真结果或不同场景测试数据作为最终性能签核。
