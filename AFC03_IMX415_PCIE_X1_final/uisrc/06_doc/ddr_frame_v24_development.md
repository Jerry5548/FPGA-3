# DDR v24 启动帧保护

版本：BAR0+0x5C = `0x56440024`。

## 触发问题与处理范围

v23 上板日志显示首批成功解码的帧号为 1、2、8，三帧均为 1920x1080
RGB24（每帧 6,220,800 字节），CRC、解码和格式错误为零；DDR_INVALID
从 0 增至 1，但 AXI 读写错误和两级 FIFO 丢数为零。
这提示启动帧 0 可能被拒收，现有日志尚不足以证明具体标记错误或根因。

v24 在原 PCIe 工程中加入显式启动保护：每次启用捕获后，在有效输入
中观察到的第一帧完整跳过，从第二个有效 SOF 起连同首个数据字写入
DDR。开始时无 SOF 的尾部数据同样不进入捕获 FIFO。主动跳过的帧
保留在捕获帧号序列中，但不计为 DDR_INVALID 或 FIFO 丢数。

该措施用于验证启动瞬态的假设，不把所有错误变成正常跳帧；后续短帧、
错误标记、混帧及读写错误仍由原有校验拒绝，测试仍要求错误计数为零。

## 实现与观测

- `ddr_camera_frame_path` 增加参数 `SKIP_STARTUP_FRAME`，默认 0 保留旧
  行为。板级 `pcie_ddr_camera` 将其设为 1。
- 启动状态在捕获禁用时清除，在软复位时连同 FIFO/DDR 请求端清除。
- 不改变原 DDR 双槽、LZ77 编码、RK 解码格式或预处理模式 0～4。
- 模式 5～7 继续为未实现的边缘检测预留。
- 新寄存器 BAR0+0xF0 = `DDR_STARTUP_SKIPS`：每次启用时主动跳过的
  第一个观察帧数量。软复位后一次测试应为 1；无软复位的多次启用会累计。
- D4 继续仅表示槽位忙时整帧跳过；D8 继续仅表示进入 DDR 校验的坏帧。
- 测试脚本要求 v24，保留严格完整性判定并检查启动跳过数为 1。
  `ddr_timeline.log` 记录运行中的计数，`before_stop.log` 记录停机前 D8。
  采样行中各寄存器顺序读取，不是同时锁存的快照。

## 验证

ModelSim 原 DDR 100 帧/随机时钟与背压/双槽保护/错误注入回归通过。
新增启动测试验证：

- 启动前无 SOF 尾部和第一帧不写入 DDR。
- 第二帧包括 SOF 上的数据字，完整数据和捕获帧号保持一致。
- 第一次启动跳过之后的短帧仍被拒收和计数。
- 禁用、重新启用及多次软复位都会重新进入保护状态。
- 生产配置开启保护后，经 DDR → LZ77 → Python 解码的 10 帧精确
  字节、CRC、RGB24 几何和帧号匹配。

可用 `uisrc/02_sim/c2h_regression/run_ddr_frames.ps1` 重现。
行为模型不验证真实 MIPI/ISP 启动序列、DDR PHY 电气行为或板级时序。

TD 综合、实现、位流及上板结果需以实际生成的 v24 发布包为准。
旧 v23 位流不能用于验证本次保护；旧发布包保持原样。
