# 预处理模式分配

2026-10-08 更新：按用户指定 MIPI test1.1 工程移植，v25 将模式 5、6
分配给灰度＋中值、灰度＋Sobel；模式 7 继续预留。

| 模式 | 功能 | 状态 |
| --- | --- | --- |
| 0 | 原图 RGB | 已实现 |
| 1 | 灰度 | 已实现 |
| 2 | 灰度＋高斯滤波 | 已实现 |
| 3 | 灰度＋直方图均衡 | 已实现 |
| 4 | 灰度＋高斯滤波＋直方图均衡 | 已实现 |
| 5 | 灰度＋3×3 中值滤波 | v25 RTL 已接入；中值用于降噪 |
| 6 | 灰度＋3×3 Sobel | v25 RTL 已接入；默认阈值 128，输出黑白边缘 |
| 7 | 边缘检测预留 3 | 未实现，具体算法待定 |

源 MIPI VPI 的 11110101/11110110（F5/F6）分别对应 PCIe 编号 5/6。
PCIe 通过 BAR0+0xA4 控制，不需要接入源工程 VPI 模块。

当前 deploy 脚本允许 0～6，7 返回退出码 2。mode_control.sh 在写入
5/6 前检查位流至少为 v25；test_lz77_frames.sh 严格要求 v25。
v23/v24 RTL 只支持 0～4，不能用旧位流验证 5/6。

image_preprocess_quad 在 DDR 完整帧缓存和 LZ77 之前完成处理。
灰度/边缘值复制到 RGB 三通道，保持 RGB24、图像尺寸和 SOF/EOL 一致。
F4/F8 分别读取中值/Sobel 协议错误计数。硬件是否可用以生成位流的
时序报告和上板验收为准，RTL 接入不等于时序或硬件验证完成。

原 v23/v24 独立发布包保持原样，脚本必须与发布包内位流版本配套。
