# LZ77 v22 boundary and FIFO diagnostic update

This update follows the RK receiver geometry regression passing on hardware
(`lz77-rx-geometry-20261006b`). It is a debugging update, not proof of complete
camera-frame capture or timing closure.

## Implemented

- RGB byte serializer uses one-beat lookahead. An early SOF closes the
  preceding shortened image and increments errors. Orphan frame tails are
  dropped. Missing LAST is bounded by the configured image size, with an
  error count. Neither case recovers missing camera pixels.
- Formatter cannot acknowledge the next image token on the cycle it
  transitions to the current image footer. Previously that token was lost.
- C2H packer carries bytes across word/beat boundaries. Partial TKEEP is
  emitted only with TLAST, including 14+4 byte and final-word carry cases.
- Serializer/formatter/encoder errors are summed for BAR0+0xBC.
- Compression headers use a local sequence captured at accepted byte SOF,
  instead of camera sticky diagnostic flags. It counts compression input
  starts, not every physical camera exposure; it resets on soft reset.
- Inactive compression no longer consumes the camera's non-handshaken
  beats or unselected C2H ready signals. Stop and soft-reset before switching
  C2H format; live mid-packet switching is not supported by this change.
- Preprocessing input valid is qualified with the upstream ready handshake.
  A stalled ISP beat is not processed repeatedly.
- Camera FIFO has a synchronous ERAM read and a held output slot. Synthesis
  before the final handshake change mapped `u_demo_fifo` to 5 ERAMs (zero
  distributed RAM), versus 1664 distributed RAM LUTs in the interim design.
- BAR0+0xC8 counts processed output beats lost when the camera FIFO is full
  and camera enable is active. It is not a complete upstream/MIPI drop
  counter. Diagnostic read decode is extended to 0xC8.
- Source version register is `0x56440022`.

## Verification

Run `uisrc/02_sim/c2h_regression/run_frames.ps1` from PowerShell. ModelSim
tests cover 100 small 16x16 frames under backpressure, early SOFs, orphan
data, missing LAST, final-token transition, word-packer carries and packet
TKEEP rules, FIFO full/empty/order/wrap/reset, and preprocessing input stalls.
`check_frame_streams.py` compares raw decoded bytes with the test inputs,
checks sequence and CRC, and verifies that the short image is rejected by
RGB24 geometry validation. These tests passed locally on 2026-10-06.

## Board procedure

Copy `deploy/test_lz77_frames.sh` and `deploy/diag_lz77.sh` into the board's
`/home/linaro/deploy`. The existing `deploy/rk3576` receiver must remain at
`lz77-rx-geometry-20261006b` or newer. Stop HDMI/GStreamer/C2H readers first.

```bash
cd /home/linaro/deploy
bash test_lz77_frames.sh 0x21200000 3
```

This one-terminal test verifies FPGA v22, resets the pipeline, starts RX,
then enables the camera. It collects RX/register/kernel logs into a unique
`/tmp/lz77-diag.*` directory and disables the producer on return. It does
not unload drivers, change the device tree or write image files.

If reception fails, send `rx.log`, `after.log`, and `dmesg.log` from the
printed directory. A nonzero C8 demonstrates processed FIFO data loss;
nonzero BC demonstrates detected compression input/formatter errors.
Zero counters do not prove image identity or rule out earlier upstream
losses or physical timing failures.

## Outstanding acceptance

The PCIe project has no DDR frame store. A 1024-entry FIFO and serial
byte encoder cannot guarantee lossless ingestion of arbitrary uninterrupted
1080p60 RGB24 source data. Frame storage, appropriate rate/throughput and
admission control still need implementation for robust continuous camera
capture. The histogram critical paths and clock/reset constraints also
remain to be resolved. No claim of board 100-frame acceptance is made.
